# Simulator

On a Mac with Xcode, agents can use Xcode's iOS simulators to check the apps they build, and you can watch and use the same device in the side panel's **Simulator** tab. Four tools (`SimulatorControl`, `SimulatorSnapshot`, `SimulatorAct`, `SimulatorScreenshot`) are offered when Xcode's simulators are found. API models get them as built-in tools; Claude Code and Codex get them from Cavvy's own MCP server (`mcp__cavvy__simulator_control` and the rest). The usual loop: build the app with `xcodebuild` for the simulator, `SimulatorControl action=boot`, `install` the `.app`, `launch` it by bundle id, read the screen with `SimulatorSnapshot`, and act with `SimulatorAct`.

- **No Simulator window.** Cavvy drives the device through Xcode's own frameworks, as Xcode's Simulator app does, with a small helper it builds with your Xcode's `swiftc` the first time it's needed (a few seconds) and keeps in `~/.cavvy/simulator`. Touches and keys reach the device as its own touch screen and hardware keyboard, the screen comes from its framebuffer, and what's on it from its accessibility tree. The buttons are Home and the side (lock) button; Siri's isn't offered, as pressing it ends SpringBoard on Xcode 27. The helper runs while a session uses a device and stops a minute after nothing does, or when the device shuts down (its screen and input don't survive a restart: the next use starts a new one). Sessions on the same device, or Cavvy windows, each with their own helper, work side by side. iPhones and iPads on iOS runtimes are offered; watchOS, tvOS and visionOS aren't.
- **Snapshots are text.** The screen comes back as an outline from its accessibility tree: buttons, text, fields, cells and switches with labels, values and identifiers, and a ref like `[e12]` on each, which stands for the middle of the part of it that's on screen. Elements wholly off screen are left out; a chosen row (a checkmarked option) says `(selected)`, and a field's value shows whole. A web page's elements live in another process the tree doesn't reach, so the outline also has the text Vision reads from the screen's picture that the tree hasn't got, in any script it reads, as `seen "…"` lines with refs of their own: links side by side that Vision reads as one line are split, and the status bar and icons read as a letter are left out. `wait` finds that text too, a phrase that wraps onto the next line included. The picture also checks the tree, which can be behind the screen: read while the screen moves (a page sliding in, the page before still in the tree), both are read again until it's still; when the picture doesn't show most of what the tree has (after Home, the tree names the app for a second or more), they're read again for up to 2.5 seconds, and the outline says so if they never agree. On an iPad, an app in a window over another isn't read: the tree is the full-screen app's. (Vision's models load in the background when the helper starts: in under a second once they have on this Mac, about a minute the first time. macOS keeps them for the helper's name, which a new build keeps.) Coordinates are in points, and a screenshot is taken at the screen's size in points, so a place in it is a place to tap. Refs last until the next snapshot; each action returns a new outline once the screen has been still for a moment (and at least 0.6 seconds: an app can take half a second to start showing a page), and `launch`, `open_url` and Home first wait for what they open to be in front. `launch` brings an app that's running to the front as it is (with launch arguments, which only a start takes, it restarts it), and an app that quits as it starts is an error. Text a US keyboard can type is typed key by key when the device's hardware keyboard has the U.S. layout (keys are where they are: a German layout would swap Y and Z); other text, and any on another layout, is pasted through the device's pasteboard. Typing with `submit` sends the keys at the pace iOS takes them and waits a second before Enter, which otherwise overtakes the end of the text.
- **Starting a device.** A device the agent starts is used by its session from then on; with none named, the session's device is the one it used last, else a booted one, else the newest iPhone. Right after a device starts, its accessibility service can take a while to answer, and sometimes doesn't until the device's bridge to the Mac restarts: Cavvy restarts it (at most every half minute) when the screen can't be read, and waits until the home screen has filled in before answering a boot.
- **Permissions.** Listing devices, snapshots, screenshots and waiting are read-only and never ask. Starting, shutting down, installing, launching and acting ask like other execute-level tools. Allowing one for the session allows `SimulatorAct` whole, and `SimulatorControl` one action at a time (`SimulatorControl(launch)`, which a rule can name too), so allowing launches doesn't allow shutting the device down. Plan mode allows reading, not starting or touching. In auto mode the reviewer decides, except for Claude Code's and Codex's calls, which run without it as the browser tools' do. Rules naming `mcp__cavvy__simulator_act` apply to their calls too.
- **In the GUI,** the Simulator tab shows the session's device: its screen, drawn at the pane's size and sent only when it changes (quick pictures while it moves, a sharp one once it stops), the device menu (choosing one that's off starts it), Home and Shut down. Click to tap, drag to swipe, scroll to drag the screen, and type to use its keyboard; pasted text goes as text. When the agent uses the simulator while the tab isn't showing, the tab gets a dot and a toast says so. When you've used the device since the agent last looked (a touch, a scroll, typing or a button; not a modifier key alone), its next result says so. It works in the desktop app and in `cavvy gui` in a browser, since the simulator runs next to the server.
- **Settings.** `simulator.enabled` (default `true`; Settings → General → Simulator) turns the tools and the tab off; any settings file can turn it off, none back on. `CAVVY_SIMULATOR=0` hides the simulators from that run.
