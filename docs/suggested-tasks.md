# Suggested tasks

While an agent works, it may come across a problem that has nothing to do with its task: a bug, a UI glitch, a test failing for a reason its change didn't cause. Instead of fixing it there or only mentioning it, it suggests a task: a card in the conversation with a title, what it saw, and the prompt a new session would start with. Nothing starts until you press Start. Whether an agent suggests one on its own depends on the model and on how the problem shows up: a test that fails while it works is suggested far more often than a bug it only reads past, which it may just mention in its reply.

On the card you pick the model and effort, the machine (this Mac or one of your connected servers), the folder, and whether it gets a new worktree; you can edit the title and the prompt. Then Start, or Dismiss (Restore brings it back).

- **Starting** makes a session on that machine as if you'd started it: the prompt is your first message, and its agent is told, out of sight, which session suggested it, and can message that session where Cavvy allows messages between the two. It runs in your default mode for that folder. In a new worktree, the branch is `fix/<title>`, or `fix/<title>-2` and so on when that's taken here or on a remote (`fix-<title>` in a repository with a branch named `fix`), and its agent is told that paths in the prompt mean the same files there. Pressing Start again (a second window, a retry after an error) gives the session already started, not a second one, as long as both pick the same machine. If a `UserPromptSubmit` hook refuses the prompt, nothing starts: the card shows why, and you can edit the prompt and Start again (in the same worktree, if one was made). A hook that takes longer than its timeout plus 3 seconds (30 at most) to answer doesn't hold up the start: if it then refuses, the prompt goes back to the session's message box.
- **The prompt is the agent's words.** Read it before you start it, as you would a message you send. Characters that don't show (direction marks, zero-width spaces) are shown as `⟨U+…⟩`.
- **Limits:** at most 3 a turn and 20 waiting in a session. A suggestion with the same title (ignoring case) as one waiting or one you dismissed is refused; once one is started, the same title can come up again.
- **Noticing them:** while the session is open in Cavvy (a window shows it, or it's working), its row in the sidebar counts the ones waiting; and the notification at the end of a turn says how many it suggested ("· suggested 1 task").
- **Where:** the main agent of a session in the app, on any model: Cavvy's own models get `SuggestTask`, Claude Code and Codex get `suggest_task` from Cavvy's MCP server. Not in the terminal, in `cavvy -p` runs, or to sub-agents. Claude Code's and Codex's own sub-agents can see `suggest_task`. A call Cavvy can tell is a sub-agent's is refused, and the sub-agent is told to put the problem in its report so the main agent can suggest it; one it can't place within a couple of seconds counts as the main agent's (nothing starts without you either way).
- A session open in the terminal can't be started from: close it there first. Rewinding past a suggestion takes its card away; a fork doesn't copy the cards.

**Cost:** the tool's description adds about 420 tokens to every request a Cavvy model makes (estimated at 4 characters a token). Claude Code gets a 431-character paragraph in its system prompt, since it keeps only the start of Cavvy's MCP server instructions and lists the tool by name until the agent loads it; Codex gets the same paragraph at the end of those instructions.
