# Mac apps

With it turned on, agents can use apps on your Mac, each only once you've said yes to it. Four tools (`DesktopControl`, `DesktopSnapshot`, `DesktopAct`, `DesktopScreenshot`) are offered to the models Cavvy runs itself (API models and their sub-agents), and to Claude Code from Cavvy's own MCP server (`mcp__cavvy__desktop_control` and the rest), since it has no computer use of its own. Codex uses its own computer use ([below](#codex)) and never gets them. The usual loop: the agent asks for an app by name (`DesktopControl action=request_access app=TextEdit`), you're asked "Use TextEdit?", it brings the app to the front (`action=open`), reads it with `DesktopSnapshot`, and acts with `DesktopAct`.

- **Turning it on.** `desktop.enabled` (default `false`; Settings → General → Mac apps). Only your own settings (`~/.cavvy/settings.json`) can turn it on: a project's can't hand your Mac to an agent. Any settings file can turn it off. Off, or not on macOS, the tools aren't offered and cost nothing in a request.
- **Each app is yours to give.** You're asked about every app, in every permission mode: plan and bypass included, past any rule that allows `DesktopControl`, any hook, and auto mode's reviewer. A yes lasts until the session ends (`/clear`, `/resume` or a fork in the terminal app start one; so does Cavvy quitting), and covers that app's windows only. The app is the one macOS knows by that name's bundle id: a copy elsewhere claiming another app's id isn't found. Its sub-agents share the session's apps. Never offered, and refused before you're asked: terminals (Terminal, iTerm2, Ghostty, Warp, WezTerm, Alacritty, kitty and the like), password managers and credential stores (Passwords, Keychain Access, 1Password, Bitwarden and the like), and Cavvy itself, along with the terminal Cavvy runs in. Cavvy's own page in a browser (`cavvy gui`) is never read, clicked or typed into, nor in a screenshot, even in a browser you gave: it's told by its title ("… · Cavvy"). Apps are matched by bundle id once found, and by name before; `NEVER_OFFERED` in `src/desktop/apps.ts` has the list, which the helper also checks itself, whatever it's sent. Apps that can run commands themselves are offered (Script Editor, Automator, Shortcuts, a code editor with a terminal, Finder opening a script): giving one gives the agent what it can run there.
- **What reaches only the apps you gave.** Each read and action carries the processes of your apps that are running, and Cavvy's helper checks against the screen as it is, right before each event goes out:
  - a click (or a drag's ends, or a scroll) goes only to a point where the accessibility hit-test finds one of your apps, inside one of its windows (its open menus, and a sandboxed app's Open and Save panels, count as its own). The Apple menu is no app's;
  - a key goes only while one of your apps has keyboard focus: typing is checked before every character. Shortcuts that are the system's (log out, lock the screen, force quit, pictures of the whole screen, moving the keyboard to the menu bar, the Dock or the status menus) and the Apple menu's are refused, judged by the keys that would go out; so are keys while the Apple menu is open, and moving between open menus with the arrows;
  - a screenshot is of your apps' windows on the display with most of them, cut to them, with every other window left out (not covered), at one pixel a point;
  - a snapshot reads one of your apps (the one in front, or one by name).
- **You can always take over.** While Cavvy's helper runs, it watches the Mac's mouse and keyboard (listening only) and tells your input from its own; it won't act when it can't watch. When you move the mouse, click, scroll or type during an action, the action stops at once and its result says you used the Mac, with how much was typed; a click or key that had already gone is done, and a drag goes back to where it started. Between actions, clicking, typing or scrolling in one of the apps you gave makes the next result say so, and a ref from before is refused; what you do elsewhere, answering Cavvy's prompts included, doesn't count (unless Cavvy's page is in a browser you gave: input there counts as using that browser). Esc in Cavvy stops an action too, while Cavvy has focus.
- **Snapshots are text.** An app comes back as an outline from its accessibility tree: its menu bar on one line, an open menu's items, each window with where it is, and in it buttons, text, fields, checkboxes, rows with labels and values, and a ref like `[e12]` on each, standing for the middle of what of it is inside its window. What's scrolled out of its window, scroll bars and a minimized window's contents are left out; what's typed in a password field isn't shown, or said back. Coordinates are screen points from the top left of the main display. At most 3,000 elements are read from an app, and the outline stops at 24,000 characters; both say so.
- **Refs.** A ref is good for one action, which returns a new outline with new refs. Before a ref is used, what it stood for is looked for again: the same kind of element called the same at the same place (a field whose text changed is still the field). If it's gone, or you've used the Mac since the agent last looked, nothing is done and the agent gets the app as it is. (After the helper has stopped for being idle, nothing watched meanwhile: what's there decides alone.)
- **Keys and text.** Text is typed a character at a time as characters, whatever the keyboard layout; a combination (`Meta+S`) presses the key that types that character on the current layout, with Shift when the character needs it. `clear` selects all in the field (`Meta+A`) and deletes it.
- **macOS permissions.** The helper, Cavvy Desktop Control, is built with your `swiftc` (Xcode or its command line tools) the first time it's needed, a few seconds, and kept in `~/.cavvy/desktop`. macOS asks about it, not Cavvy or your terminal: it starts by making itself responsible for itself, so the grants are its own, whether Cavvy runs as the desktop app or from a terminal, and Cavvy itself never holds them. A shell command that names the helper, its name or its folder however it's written, asks you every time, in every mode, and auto mode's sandbox can't reach the folder; that's a guard, not a wall, since a command that hides the name isn't caught. The helper takes commands only from the Cavvy that started it, which hands it a secret made for that start over a pipe only the two share: that stops other programs from simply running it, not something already running as you. It needs Accessibility (reading apps, clicks and keys, watching your input) and, for screenshots, Screen & System Audio Recording. When one is missing, Cavvy asks macOS to show its own prompt (once each time the helper starts) and the result says in one line what to turn on, in System Settings → Privacy & Security. The same source built again comes out the same (measured: the same code hash), so a grant should last until Cavvy changes the helper. What macOS does with the switch then isn't checked yet: the result says to remove the old entry with − and try again.
- **Permissions in Cavvy.** Listing apps, snapshots, screenshots and waiting are reads and never ask. Opening an app and acting ask like other tools that execute. A yes to a click or a key covers that call; allowing for the session allows `DesktopAct` whole, and `DesktopControl(open)` by itself. Plan mode reads, and can ask for an app, but doesn't open, click or type. In auto mode the reviewer decides on actions, never on apps. Rules naming `DesktopAct` or `DesktopControl(open)` apply as usual, rules naming `mcp__cavvy__desktop_act` and the rest apply to Claude Code's calls too, and deny rules always win.
- **The helper** starts on the first call and stops a minute after the last one ends; while it isn't running, nothing watches the Mac. One serves every session.

## Codex

Codex sessions use Codex's own computer use, as the ChatGPT app sets it up, under the same setting and the same rule: each app is yours to give.

- **What's needed.** `desktop.enabled`, and Computer Use set up in the ChatGPT app, which turns on its `unified-computer-use@openai-bundled` plugin in your Codex configuration. Cavvy leaves that setup as it is: it starts nothing of the app's and writes nothing to your Codex configuration. macOS asks about the permissions of ChatGPT's Computer Use, not Cavvy's. Not set up, a Codex session says once how to set it up, and runs without.
- **Approvals.** Codex asks for an app when it first needs it, and you're asked "Use Safari?" in every mode, bypass included: no rule, hook, auto mode's reviewer or bypass answers it. In plan mode Codex doesn't use apps at all (its calls act as well as read, so they're refused). Allow once; for this session (Cavvy answers yes for that app until the session ends, unless a deny rule for `DesktopControl` is added meanwhile); or always, which Codex's computer use keeps itself, for later sessions and the ChatGPT app too. Never offered, and refused without asking: the apps listed above, which Codex is also told to deny (`computer_use.macos.bundle_ids`). A link it asks you to open, to set it up, is cancelled rather than declined, as a decline would be kept as a refusal. Each call itself (`mcp__cua_repl__js`) asks like any MCP tool's; in bypass Cavvy answers those, and Codex runs on-request instead of never: under never, Codex says yes to an app by itself.
- **Off.** With `desktop.enabled` off (turning it off or on mid-session takes effect from the next message), or for a read-only agent, Codex's computer use is off in Cavvy's sessions, also where your Codex configuration turns it on: its plugins (`unified-computer-use@openai-bundled`, `computer-use@openai-bundled`) and servers named `cua_repl`, `computer-use` or `node_repl` are turned off for the session. A project's Codex configuration can't turn it on.
- **Commands naming the helper.** Codex runs some commands without asking Cavvy (in auto and bypass), so while Mac apps is on, or once the helper has been built, Cavvy adds its PreToolUse hook to Codex, which Codex runs before every tool call in every mode: a shell command naming the helper asks you there, every time, as above, and only once even where Codex then asks too. So does a call of Codex's computer use whose code names it, in that hook and in Codex's own approval of the call (auto mode's reviewer answers that approval, so there only the hook sees it); code it loads from a file, or a name it puts together, isn't seen. Each tool call then makes one round trip to Cavvy. A Codex without hooks (before 0.160) asks about every command in bypass instead; in auto it isn't guarded.
- **In the transcript.** A call shows what it does, then in which app once Codex says: "TextEdit: Type the note".
- **What was measured** (Codex 0.167, ChatGPT 26.1106). Codex passes each app approval on from its computer use (an MCP elicitation from `cua_repl` naming the app's bundle id), and says which app a call used in its result. It doesn't pass `computer_use.macos.bundle_ids` on, and asks about an app it denies all the same, which is why Cavvy refuses those apps itself. `features.computer_use=false` doesn't turn computer use off; turning its plugin off does.
