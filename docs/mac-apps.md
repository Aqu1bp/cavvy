# Mac apps

With it turned on, agents can use apps on your Mac, each only once you've said yes to it. Four tools (`DesktopControl`, `DesktopSnapshot`, `DesktopAct`, `DesktopScreenshot`) are offered to the models Cavvy runs itself (API models and their sub-agents), and to Claude Code from Cavvy's own MCP server (`mcp__cavvy__desktop_control` and the rest), since it has no computer use of its own. Codex uses its own computer use ([below](#codex)) and never gets them. The usual loop: the agent asks for an app by name (`DesktopControl action=request_access app=TextEdit`), you're asked "Use TextEdit?", it brings the app to the front (`action=open`), reads it with `DesktopSnapshot`, and acts with `DesktopAct`.

- **Turning it on.** `desktop.enabled` (default `false`; Settings → General → Mac apps). Only your own settings (`~/.cavvy/settings.json`) can turn it on: a project's can't hand your Mac to an agent. Any settings file can turn it off. Off, or not on macOS, the tools aren't offered and cost nothing in a request.
- **Each app is yours to give.** You're asked about every app, in every permission mode: plan and bypass included, past any rule that allows `DesktopControl`, any hook, and auto mode's reviewer. A yes lasts until the session ends (or Cavvy quits: a session resumed later asks again), and covers that app's windows only. Its sub-agents share the session's apps. Never offered, and refused before you're asked: terminals (Terminal, iTerm2, Ghostty, Warp, WezTerm, Alacritty, kitty and the like), password managers and credential stores (Passwords, Keychain Access, 1Password, Bitwarden and the like), and Cavvy itself, along with the terminal Cavvy runs in. Apps are matched by bundle id once found, and by name before; `NEVER_OFFERED` in `src/desktop/apps.ts` has the list.
- **What reaches only the apps you gave.** Each read and action carries the processes of your apps that are running, and Cavvy's helper checks against the screen as it is, right before each event goes out:
  - a click (or a drag's ends, or a scroll) goes only to a point where the accessibility hit-test finds one of your apps, inside one of its windows (its open menus, and a sandboxed app's Open and Save panels, count as its own). The Apple menu is no app's;
  - a key goes only while one of your apps has keyboard focus: typing is checked before every character;
  - a screenshot is of your apps' windows on the display with most of them, cut to them, with every other window left out (not covered), at one pixel a point;
  - a snapshot reads one of your apps (the one in front, or one by name).
- **You can always take over.** While Cavvy's helper runs, it watches the Mac's mouse and keyboard (listening only) and tells your input from its own. When you move the mouse, click, scroll or type during an action, the action stops at once (a held button is let go first) and its result says you used the Mac, with how much was typed. Between actions, the next result says so, and a ref from before is refused. Esc in Cavvy stops an action too, while Cavvy has focus.
- **Snapshots are text.** An app comes back as an outline from its accessibility tree: its menu bar on one line, an open menu's items, each window with where it is, and in it buttons, text, fields, checkboxes, rows with labels and values, and a ref like `[e12]` on each, standing for the middle of what of it is inside its window. What's scrolled out of its window, scroll bars and a minimized window's contents are left out; what's typed in a password field isn't shown, or said back. Coordinates are screen points from the top left of the main display. At most 3,000 elements are read from an app, and the outline stops at 24,000 characters; both say so.
- **Refs.** A ref is good for one action, which returns a new outline with new refs. Before a ref is used, what it stood for is looked for again: the same kind of element called the same at the same place (a field whose text changed is still the field). If it's gone, or you've used the Mac since the agent last looked, nothing is done and the agent gets the app as it is.
- **Keys and text.** Text is typed a character at a time as characters, whatever the keyboard layout; a combination (`Meta+S`) presses the key that types that character on the current layout. `clear` selects all in the field (`Meta+A`) and deletes it.
- **macOS permissions.** The helper, Cavvy Desktop Control, is built with your `swiftc` (Xcode or its command line tools) the first time it's needed, a few seconds, and kept in `~/.cavvy/desktop`. macOS asks about it, not Cavvy or your terminal: it starts by making itself responsible for itself, so the grants are its own, whether Cavvy runs as the desktop app or from a terminal, and Cavvy's other processes (an agent's shell commands) never get them. It needs Accessibility (reading apps, clicks and keys, watching your input) and, for screenshots, Screen & System Audio Recording. When one is missing, macOS shows its own prompt once and the result says in one line what to turn on, in System Settings → Privacy & Security. The same source built again comes out the same, so a grant lasts until Cavvy changes the helper; macOS then keeps the switch on but no longer counts it, and the result says to remove the old entry with − and try again.
- **Permissions in Cavvy.** Listing apps, snapshots, screenshots and waiting are reads and never ask. Opening an app and acting ask like other tools that execute. A yes to a click or a key covers that call; allowing for the session allows `DesktopAct` whole, and `DesktopControl(open)` by itself. Plan mode reads, and can ask for an app, but doesn't open, click or type. In auto mode the reviewer decides on actions, never on apps. Rules naming `DesktopAct` or `DesktopControl(open)` apply as usual, rules naming `mcp__cavvy__desktop_act` and the rest apply to Claude Code's calls too, and deny rules always win.
- **The helper** starts on the first call and stops a minute after the last one ends; while it isn't running, nothing watches the Mac. One serves every session.

## Codex

Codex sessions use the computer use that comes with the ChatGPT app, under the same setting and the same rule: each app is yours to give.

- **What's needed.** `desktop.enabled`, and the ChatGPT app in Applications (`/Applications` or `~/Applications`). Cavvy starts the app's own computer-use runtime for each Codex session, for desktop control only, as an MCP server named `cua_repl`; nothing is written to your Codex configuration. Its macOS permissions are those of the ChatGPT app's Computer Use, which asks for them itself. Without the app, a Codex session says once that it needs it, and runs without.
- **Approvals.** Codex asks for an app when it first needs it, and you're asked "Use Safari?" in every mode, plan and bypass included: no rule, hook, auto mode's reviewer or bypass answers it. Allow once; for this session (Cavvy answers yes for that app until the session ends); or always, which Codex's computer use keeps itself, for later sessions and the ChatGPT app too. Never offered, and refused without asking: the apps listed above, which Codex is also given as denied (`computer_use.macos.bundle_ids`). A link it asks you to open, to set it up, is cancelled rather than declined, as a decline would be kept as a refusal. Each call itself (`mcp__cua_repl__js`) asks like any MCP tool's; in bypass Cavvy answers those, and Codex runs on-request instead of never, as under never it would say yes to an app by itself.
- **Off.** With `desktop.enabled` off, a read-only agent, or no ChatGPT app, Codex's computer use is off in Cavvy's sessions, also where your own Codex configuration turns it on: its plugins (`unified-computer-use@openai-bundled`, `computer-use@openai-bundled`) and servers named `cua_repl`, `computer-use` or `node_repl` are turned off for the session. A project's Codex configuration can't turn it on. A server of your own named `cua_repl` keeps it off (Cavvy won't merge its settings into yours) and says so.
- **In the transcript.** A call shows what it does, then in which app once its result says: "TextEdit: Type the note".
- **What was measured** (Codex 0.167, ChatGPT 26.1106). A plain Codex CLI has no computer use: the ChatGPT app's `openai-bundled` marketplace loads only from the copy the app keeps in Codex's home, and its `unified-computer-use` plugin's `cua_repl` is a disabled placeholder the app fills in. A thread's own `cua_repl` replaces it. Codex passes the server's app approvals on unchanged (`_meta.connector_id: "computer-use"`, the app's bundle id in `tool_params.app`), and returns `codex/toolSurface` in the call's result. `features.computer_use=false` doesn't turn a `cua_repl` server off.
